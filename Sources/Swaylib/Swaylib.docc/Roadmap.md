# Roadmap

Where Swaylib is and where it is going. Finished items stay in their section, checked off.

## MVP

- [x] raylib built from source by SwiftPM on Linux, Windows and macOS, with GLFW (RGFW on macOS).
- [x] Generator for enums, option sets and named colors from `raylib_api.json`.
- [x] Window, frame loop and the `Begin`/`End` scopes as closures.
- [x] Shapes, text, textures, render textures, images, fonts, shaders, 2D and 3D cameras.
- [x] Keyboard, mouse, gamepad, touch and gestures.
- [x] Sounds and music.
- [x] Unattended runs with `SWAYLIB_FRAMES` and `SWAYLIB_SCREENSHOT`.
- [x] Tests that draw into a render texture and check pixels, run under Xvfb on CI.
- [x] DocC documentation with a generated API coverage page.
- [x] CI results on Windows and macOS confirmed green.

## Backends

- [x] `ANGLE` trait on Linux and Windows: raylib built for OpenGL ES 3 on an EGL context, tested on
  CI against Mesa's EGL and GLES.
- [x] All tests pass on prebuilt ANGLE on Linux, on its OpenGL, Vulkan and SwiftShader backends.
- [ ] `ANGLE` trait on macOS. raylib's RGFW platform only creates native OpenGL contexts, so this
  needs an EGL path in RGFW's raylib platform (upstream) before the build stops refusing it.
- [x] ANGLE binaries from a Swaylib fork,
  [swift-gamedev/angle-prebuilt](https://github.com/swift-gamedev/angle-prebuilt), with dated
  releases, checksums, and SwiftShader built with its X11 window support.
- [ ] Script that fetches those checksummed ANGLE libraries for each platform.
- [ ] CI that runs the tests on ANGLE itself, not only on Mesa's EGL.
- [ ] Choosing ANGLE's platform (Vulkan, D3D11, Metal) from Swift through GLFW's hint.
- [ ] ANGLE as the default on macOS.
- [ ] Render tests on ANGLE's SwiftShader backend, so Windows CI can run them too.
- [ ] raylib's software renderer (`rlsw`) and `PLATFORM_MEMORY` as a headless trait for CI.
- [ ] Zink: documented, tested setup on Mesa.

## Platforms

- [ ] Native Wayland on Linux (needs `wayland-scanner` output checked in or generated by a plugin).
- [ ] GLFW on macOS, if SwiftPM ever allows compiling Objective-C without ARC per target; until then
  macOS runs on RGFW, and the ANGLE trait there waits on an EGL path in raylib's RGFW platform.
- [ ] Report RGFW's `NSApp` release in `RGFW_deinitPlatform` upstream and drop the shim workaround
  once a fixed RGFW ships in raylib.
- [ ] A person has run the examples on Windows and macOS.
- [ ] Drop the miniaudio submodule once a raylib release bundles miniaudio 0.11.26 or newer, which
  opens PulseAudio devices whose native format is s24_32.

## API coverage

- [ ] Models, meshes, materials and animations (`rmodels`).
- [ ] Audio streams and waves.
- [ ] The rest of `rshapes` (splines, collision helpers) and `rtext` (codepoints, glyph info).
- [ ] File system and file data helpers from `rcore`.
- [ ] `rlgl` for advanced users, in its own namespace.
- [ ] `Span`-based buffer APIs for texture and audio stream updates.

## Quality

- [ ] Reference image comparison for render tests, with a tolerance.
- [ ] Check the content of the CI example screenshots, not only that the file exists, so a blank
  frame fails.
- [ ] More examples, ported from raylib's examples directory.
- [ ] Benchmarks of the Swift layer against calling the C API directly.
